この教材では、URL 短縮サービス「shortlink」を 1 日ずつ育てます。最初は Go の標準ライブラリだけで動く小さな HTTP サーバから始め、永続化、テスト、Docker、Kubernetes、負荷試験、キャッシュ、可観測性、レートリミット、分散設計へ進みます。

大事にするのは、道具の名前を覚えることではありません。なぜその設計が必要になるのか、どの負荷や運用上の制約に効くのかを、実装と計測を通して確かめることです。

## 15日間の概要

| 日 | タイトル | 主なテーマ |
| --- | --- | --- |
| Day 1 | Go 入門と最小の URL 短縮サーバ | `net/http`、パッケージ構成、base62、メモリ保存 |
| Day 2 | API 設計とテスト文化 | JSON エラー、URL バリデーション、`httptest`、table-driven test |
| Day 3 | 永続化とインターフェース設計 | Storage インターフェース、SQLite、`context.Context`、差し替えやすい設計 |
| Day 4 | Go の並行処理とクリック統計 | goroutine、channel、race detector、graceful shutdown |
| Day 5 | Docker でコンテナ化 | multi-stage build、distroless、イメージレイヤ、非 root 実行 |
| Day 6 | Docker Compose と Postgres 移行 | Compose、Postgres、healthcheck、サービス名 DNS、接続プール |
| Day 7 | 計測: k6 ベースラインと pprof | レイテンシ、スループット、p95、k6、pprof |

## 対象読者

- Go で Web API を作りながら、バックエンド開発の基礎を固めたい人
- Docker や Kubernetes を、手順だけでなく「何を解決する道具か」から理解したい人
- スケーラビリティ、キャッシュ、可観測性、レートリミットを実装と計測で学びたい人
- 小さなサービスが本番運用に近づく過程を、段階的に追体験したい人

Go、Docker、Kubernetes の経験が浅くても進められる構成にします。一方で、各日で扱う設計判断は実務でもそのまま使うものです。すでに経験がある人は、なぜその選択をするのかを説明できるか確認しながら進めてください。

## 進め方

各日は、まず「今日のゴール」で到達点を確認します。次に概念を学び、実際のコードを読み、手元でコマンドを実行して期待出力を確かめます。最後にクイズで、表面的な操作ではなく設計理由まで理解できているかを確認します。

おすすめの進め方は次の通りです。

1. その日のページを最後まで読み、全体像をつかむ。
2. コード差分を確認し、どの責務がどのパッケージに置かれているかを見る。
3. 手順どおりにコマンドを実行し、期待出力と違う場合はログを読む。
4. クイズに答え、間違えた問題は本文とコードに戻って確認する。
5. Day 7 以降は計測値を記録し、改善前後の数字を比較する。
6. 各Dayのコードは git タグ(day01〜day15)で参照できる。

このコースの軸は「動いた」で終わらせないことです。URL 短縮という小さな題材でも、読み取りが多い、短い ID が必要、リダイレクトが遅いと体験が悪い、複数レプリカでローカル状態が壊れる、という現実的な制約が出てきます。その制約に対して、コード、インフラ、計測のどこで対応するのかを毎日少しずつ増やしていきます。
